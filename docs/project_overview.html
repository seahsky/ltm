LTM-Embodied Agent — Project Overview

A lifelong hierarchical long-term memory stack for embodied agents, extending the ReMEmbR backbone (Qwen2-VL-2B captioner + Qwen2.5-7B planner) in Habitat / HM3D ObjectNav & AudioGoal. Click any module, flow node, or card to expand the real function names & file:line they live at. Offline single file — no network.

Two-path architecture

One LTM stack, two evaluation surfaces, joined by the bridge. The dialogue path holds the actual memory classes; the embodied path reuses them unchanged and adds waypoint injection. Convention: never break the dialogue/MSC path while building the embodied path.

⬤ Load-bearing fact — the fine LTM PERSISTS across episodes
begin_episode sets self._pending = [] and the scene/episode ids — and touches nothing on self.ltm (the HierarchicalLTM built once in __init__ at memory_bridge.py:433). The fine FAISS index and its entries list are never reset between episodes. This is exactly what makes a warm revisit possible: a cold sighting written in episode N is still retrievable in episode N+1. begin_episode — memory_bridge.py:628-634

Two structural caveats (from the audit)

Scene hard-filter ⇒ no cross-env waypoint

propose_memory_candidates rejects any fine entry whose metadata["scene_id"] ≠ the current scene. A home sighting can be counted as a cross-scene recall (under LTM_CROSS_SCENE) but is never injected as a waypoint — its stored xy is in the other scene's frame. So cross-environment transfer via the fine layer is structurally impossible. memory_bridge.py:1103-1115

"3-layer" ⇒ fine + rerank in practice

The action-path retriever queries the fine layer only (self.ltm.fine.search). Mid is empty (success-gated clustering rarely fires); coarse is seeded but only feeds the S_sim rerank scorer via retrieve(), not waypoint injection. The measured effect = fine layer + memory-injected rerank. memory_bridge.py:1060; retrieve() 1435-1441

⚠ Honest callout — CLAP is a trigger/classifier ONLY; audio is a code-proven NO-OP for retrieval here

The classifier output flows only through audio_target_for_retrieval → CLASS_TO_OBJECT ({baby_cry→crib, alarm→oven, glass_break→window}), which is just the target_category string handed to the unchanged propose_memory_candidates. CLAP never enters retrieval — perception.CLAPAudioEncoder is documented as the 3-way classifier only, and retrieval stays on the proven SBERT caption path. audio_task.py:246-254; perception.py:172-176

In the M3 eval the dataset builder sets obj = anomaly_object or category and writes anomaly_object from the goal category, so anomaly_object == target_category == goal. The override therefore hands the retriever the same goal string it would query anyway → the recalled waypoint is identical with or without the sound. M3's +0.171 is pure visual revisit recall; audio is dressing for retrieval. make_audiogoal_smoke.py:165, 176-178

Audio's genuine role is the onset-GATE. gate_retrieval_target (env LTM_AUDIO_DOA) returns None — suppressing all memory injection — until the anomaly is detected. So hearing the sound is causally necessary for warm recall: no onset → no target → no injected candidate. audio_task.py:257-272; episode_runner.py:1400-1403

DOA is ITD-weak by design

estimate_doa uses ITD (cross-corr / GCC-PHAT) as primary, but SoundSpaces' Ambisonic→time-aligned-HRTF path strips broadband ITD. So when |ITD| < AUDIO_ITD_MIN_SAMPLES and a real ILD is present, the ILD sign drives azimuth; the fold-invariant lateral_sign() (+1 right / −1 left) is the cue actually used downstream — world-frame, because the render is at identity listener yaw. audio.py:286-359; memory_bridge.py:177-185

Settings — S1 / S2 / S3 (--backbone remembr)

S1 — memory off

Vanilla ReMEmbR baseline. disable_stm + disable_ltm → STM buffers nothing, no fine writes. The reference arm.

S2 — STM only

+ STM consolidation into the LTM, rerank/injection off. Isolates whether STM alone moves the metric. Decomposition control.

S3 — full system

+ memory-injected candidates + memory-weighted rerank (the proposal's modules 2–4). The treatment arm.

Decomposition: S2−S1 = STM · S3−S2 = consolidation + LTM + rerank · S3−S1 = headline. Settings run in separate processes / out-dirs (the LTM persists only within a process).

Cold vs warm, and the revisit harness

Cold vs warm

The analyzer groups episodes by (scene_id, target_category). Visit 0 = cold (no prior in the LTM); visit ≥1 = warm (the LTM may hold a prior sighting). Memory only pays off on warm. pin_episode_order pins shuffle=False + group_by_scene=True so the cold seed always precedes its warm revisits. episode_order.py:73-74; habitat_env.py:236

No --seed / RNG knob exists in the run path — warm-pose sampling is deterministic & sort-based (make_revisit_smoke.py imports no random/numpy). A genuine "different sample" requires rebuilding the dataset.

◆ Instance bottleneck & scope

SBERT carries instance signal (within-instance caption cosine 0.628 vs between-instance same-category 0.535, +0.093) but the live category query "there is a {cat}" collapses it to a 0.047 rank gap. Any head that stores more goal-ish frames surfaces more wrong-instance candidates → over-fire. The next genuinely-different lever is a better instance-discriminating embedding/detector (a separate, larger project) — not another LTM head. memory_bridge.py:126 (_GOAL_QUERY_TEMPLATE)

Scope: the positive result is within-scene, same-category recall. Recall is hard-filtered to the current scene (memory_bridge.py:1103) ⇒ cross-environment transfer is structurally absent for a waypoint.
